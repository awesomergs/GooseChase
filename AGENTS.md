# Agent instructions

Before making any change, read:
1. `MAP.md`: every file, what's in it, who owns it, how data flows. Use it to find code instead of searching.
2. `SPEC.md`: scope, the contracts between teammates, conventions, and binding rules for agents.

The short version:
- 8-hour hackathon app (Quarry: camera-verified scavenger hunts). Small and fully working beats big and half done.
- Edit only the folder your human owns. Never edit `project.pbxproj` unless asked.
- Keep the contracts in SPEC.md section 6 stable. No packages, no backend, no paid capabilities.
- If you add, rename or delete a file, or change a public type/function, update `MAP.md` in the same change.
- Build after every change; explain what you changed in 2–3 plain sentences.
